# Анализ модели — своё окно вместо штатного анализа БАЗИС

Штатный «Анализ модели» на больших моделях грузит компьютер и зависает. Этот скрипт проверяет модель
сам: один проход по объектам, дальше — быстрые расчёты по контурам и отверстиям. Кухня проверяется за
секунду-две, результат — в отдельном окне со своими настройками проверок.

Нужно: БАЗИС-Мебельщик (проверено на 2024), Windows 10/11 64-бит, интернет (см. ниже). Python и прочее ставить не надо.

## Установка

1. Скопируйте папку «Анализ модели» целиком в папку скриптов БАЗИС (например `…\Bazis\Scripts\Анализ модели`).
2. Запустите в БАЗИС скрипт `Анализ модели.js` из этой папки.
3. При первом запуске скрипт покажет **код компьютера** (он же запишется в файл «Код компьютера.txt» в папке
   скрипта). Отправьте код автору скрипта.
4. Автор пришлёт файл `license.lic` — положите его в папку скрипта и запустите скрипт ещё раз.

Лицензия привязана к компьютеру и имеет срок. Срок, номер лицензии и код компьютера видны в окне на вкладке
«О программе»; за две недели до конца срока окно напомнит. Продление делает автор у себя — новый файл присылать
не нужно, у вас продлится само. После переустановки Windows код компьютера меняется — нужна новая лицензия.

**Интернет.** Скрипт проверяет лицензию на сервере автора: при первом запуске, после каждого обновления и дальше
раз в сутки. Без интернета скрипт работает до 14 дней с последней проверки (окно показывает, сколько осталось),
потом попросит подключиться. Если часы компьютера перевести назад, скрипт откажется работать, пока время не
станет верным.

## Обновление

Окно при запуске само проверяет, нет ли новой версии. Если есть — внизу появляется кнопка «Обновить до …»,
а на вкладке «О программе» — описание изменений. Там же кнопка **«Проверить обновления»**.

Обновление скачивается с этой страницы GitHub и принимается только с подписью автора. Ваши настройки
(`Анализ модели — настройки.json`) и лицензия при обновлении не меняются. После установки окно закроется —
запустите скрипт в БАЗИС заново.

## Что в папке

| Файл | Зачем |
|---|---|
| `Анализ модели.js` | запускается в БАЗИС: проверяет лицензию и запускает анализ |
| `Анализ модели.crypt` | сам анализ в зашифрованном виде |
| `crypt_svc.exe` | проверяет лицензию на сервере автора и расшифровывает анализ |
| `Анализ_модели_UI.exe` | окно с результатами и настройками |
| `viyar_catalog.json` | выжимка каталога Вияра для проверок цвета и петель |
| `version.json`, `version.sig` | номер сборки и подпись автора |
| `license.lic` | ваша лицензия (кладёте сами) |

## Запуск

`Анализ модели.js` — проверяет модель, подсвечивает замечания и открывает окно.

**Окно «живое»: щёлкаете замечание — объект сразу выделяется в модели** (щелчок по проверке — все объекты её
замечаний). «Проверить (F5)» — перепроверка с новыми настройками. «Подсветить все замечания» / «Снять подсветку и
выделение» — тоже сразу.

Пока есть связь (вверху окна «● связь есть»), команда анализа в БАЗИС активна. Забирает она только **щелчки мыши по
модели**: камера, колесо и горячие клавиши БАЗИС работают как обычно. Поэтому (с версии 1.3):

- **Щелчок по детали в модели** — скрипт сам выделяет её (одну, как обычный щелчок БАЗИС). Мимо детали — ничего.
- **Сдвинуть / править** — выделили деталь щелчком и запускаете обычную команду БАЗИС (кнопкой или горячей клавишей).
  Она сама завершает команду анализа: выделение сохраняется, **окно остаётся** («○ БАЗИС отпущен»).
- **Вернуться к замечаниям** — запустить «Анализ модели» ещё раз (удобно назначить скрипту горячую клавишу): открытое
  окно подхватывается, модель перепроверяется — сразу видно, ушло ли замечание.

Остальное:

- **Работать в модели** — кнопка **«Отпустить БАЗИС»** в окне или Esc в БАЗИС. **Окно при этом не закрывается**,
  результаты остаются («○ БАЗИС отпущен»).
- **Снова щёлкать** — запустить «Анализ модели» ещё раз: открытое окно подхватывается (второе не открывается),
  модель перепроверяется. Либо кнопка **«Подключить»** — она работает, если один раз задать поле «Клавиша в БАЗИС»
  (горячая клавиша, назначенная скрипту в БАЗИС): тогда окно само нажимает её в БАЗИС и подключается без перепроверки,
  и даже щелчок по замечанию при отпущенном БАЗИС сам подключается и выделяет. Поле необязательное.
- Закрыли окно — БАЗИС отпускается сам. Закрыли БАЗИС — окно остаётся с последними результатами.

Почему нельзя «и щёлкать, и работать в БАЗИС одновременно»: фоновой работы у скриптов БАЗИС нет. Вне команды нет ни
таймеров, ни событий; таймер, оставшийся после конца команды, не срабатывает и может уронить БАЗИС («External exception
80000003»); COM-управления снаружи тоже нет.

Ещё в окне:
- **Подсвечивать замечания в модели при проверке** — как у штатного анализа.
- **Только выделенное** — показывать замечания, где участвует выделенный (до запуска) объект или блок.
- **Сохранить отчёт…** — текстовый файл рядом с моделью.
- **Правая кнопка по замечанию** — «Не проверять в этой проверке / вовсе»: имя, материал или блок объекта.

Объект замечания находится по ключу: UID (если есть) + имя + позиция + мировая точка начала СК. Если модель после
проверки поменяли и объект не нашёлся, окно напишет об этом — нажмите «Проверить (F5)».

Настройки (галочки, пороги, исключения, роли крепежа) запоминаются в
`Анализ модели — настройки.json` рядом со скриптом — это рабочий файл, при обновлении не перезаписывается.

## Что проверяется

| Проверка | Штатный аналог | По умолчанию | Как |
|---|---|---|---|
| Пересечение деталей | Пересечение элементов | вкл, допуск 0,1 | Панели и профили — по настоящему контуру × толщина. Касание не ошибка. Пазы и спилы детали вычитаются (с запасом по ширине профиля паза). |
| Тело фурнитуры заходит в деталь | Пересечение тела фурнитуры | выкл, допуск 1 | Грубо: по габариту крепежа. Детали, в которые сверлит этот крепёж или его соседи по блоку, не проверяются. |
| Пересечение отверстий | Пересечение отверстий фурнитуры | вкл | Цилиндры отверстий разных крепежей внутри одной детали. Соосные (муфта+шток, датчик в гнезде) — не ошибка; одинаковый крепёж в одной точке — «задвоен». Галочка «пропускать отверстия одного блока». |
| Корректность установки фурнитуры | то же | вкл, допуск 0,2 | Крепёж ни одним отверстием не входит в деталь и ничего не касается («висит»); отверстие в пласть выходит за край детали (кроме Ø20 — корпус Rafix по конструкции чуть за краем; параметр «Не проверять край для Ø», 0 — проверять все); торцевое выходит на пласть. |
| Посадка отверстий (перенос на деталь) | — | вкл, допуск 0,2 | Начало отверстия утоплено в деталь; глухое отверстие начинается в воздухе перед деталью (или за кронштейном); отверстие наклонно к детали. | Сверло выходит из детали в пустоту | — | выкл | Отверстие глубже материала на его пути. |
| Отверстие в середине торца | то же | вкл, Ø от 0, допуск 0,5 | Торцевое отверстие не по середине толщины. Группируется: деталь + крепёж + смещение ×N. |
| Скрепление панелей | то же | вкл, от 2 | Пара деталей скреплена меньшим числом крепежей. Считается по ролям крепежа (вкладка «Крепёж», ниже). |
| Деталь без крепежа | — | вкл, от 10 мм | В деталь не входит ни один крепёж и она не лежит на опоре. Клеёные/вставные (столешница, фасад посудомойки) — в исключения этой проверки. |

Не проверяются (по решению 17.11.2026): наличие материала, размер панели на плите, размер пластика, длина профиля.

## Исключения (вкладка «Исключения»)

Как в «Замене материалов и кромок»: внизу — что есть в модели (имена деталей и профилей, материалы, блоки, крепёж),
«Исключить ✕» переносит в список сверху, «Вернуть» убирает. Поле **«Для»**:
- **Все проверки** — объект не проверяется вовсе (обстановка: стены, пол, блок «Приміщення» — уже в списке). Такие детали,
  скрытые и гнутые всё равно закрывают кромки и «принимают» отверстия соседей;
- **конкретная проверка** — замечания с этим объектом в ней скрываются (в примечании проверки — «скрыто: N»).
  **«Только это ✓»** — наоборот, проверка показывает замечания только по выбранному (например, «Есть необлицованные
  кромки» — только для фасадов). Проверки со своими исключениями на вкладке «Проверки» — курсивом.

Сравнение — по равенству без учёта регистра («Пол» не задевает «Полку», блок «Стена бар» — не «Стена»);
«✕ если содержит» — по вхождению текста.

## Роли крепежа (вкладка «Крепёж»)

Для «Скрепления панелей» и «Детали без крепежа»:
- **обычный** — каждый крепёж с отверстиями в двух деталях = +1 к паре;
- **опора** — сверлит одну деталь, другая на ней лежит (тело касается её): полкодержатель/полицетримач, ножка.
  Полка на 4 полкодержателях — по 2 на каждую стойку, закреплена;
- **не крепёж** — не считается (демпфер, ручка);
- **узел** — правило по имени БЛОКА (петля/завіса, подъёмник, направляющая, Tandembox/Legrabox/Movento): части узла,
  которые сами сверлят одну деталь (чашка — фасад, планка — стойку), считаются одним соединением, и пара скреплена.
По умолчанию правила «содержит» для этих слов; список модели справа — назначить роль точному названию (точное правило
встаёт наверх и перекрывает «содержит»).

## Вияр и фасады (вкладка «Вияр и фасады»)

- Категории для «одного цвета»: список категорий Вияра, найденных в модели по артикулам (с цветами), галочками.
  По умолчанию — ручки, релинги, Gola, петли, ножки, ящики с металлическими боковинами, гардеробная фурнитура и «Гардеробное наполнение» (так у Вияра называется «джокерная система»: брючницы, вешалки), цоколи.
- Фасады: **артикулы** (через ;, `*` — любые символы, `?` — один) — петля `7?B*;7?T*;7?N*`, с доводчиком `7?B*`
  (BLUMOTION), без пружины `*.TL;70T*;78T*…`, с пружиной `71T*;79T*…`, TIP-ON `955*;956*`; и **слова в собственном
  названии сборки/фурнитуры** (не фрагмента): ручка, TIP-ON, Gola, «не петля» (заглушка, демпфер). Проверено на кухне
  «Таня финальная проверка»: 71B3550, 79B9550.83 — с доводчиком; 70T3550.TL, 78T9550.83 — без пружины; 956A1002 — TIP-ON.
- Выжимка каталога — `viyar_catalog.json` рядом со скриптом (категория, цвет, тип петли по артикулу; ~1,3 МБ).
  Обновление: `Обновить каталог Вияра.bat` в папке проекта (после прогона парсера Вияра). Парсер прошёл не все
  категории — «нет в выжимке» ≠ «нет у Вияра».

## Как писать фильтры петель, TIP-ON и ручек (вкладка «Вияр и фасады», кнопка «Как писать фильтры?»)

- **Фасад** — панель, в которую входит чашка петли (Ø20 и больше).
- **Петля** — ближайшая к чашке сборка/фурнитура С АРТИКУЛОМ («Название + Enter + Артикул»). Название фрагмента-обёртки
  («Петли 18», «Дверка L (Прямі петлі)») не смотрится.
- **Тип петли**, первое совпадение: каталог Вияра («Тип закрывания/открывания») → «Без пружины, арт.» → «Доводчик, арт.» →
  «С пружиной, арт.»; иначе «тип не распознан».
- **TIP-ON** — сборка за фасадом: каталог Вияра (Push/P2O), шаблон «TIP-ON, арт.» или слово из «TIP-ON, слова» в её
  собственном названии. **Ручка** — категория «Ручки…» Вияра или слово из «Ручка, слова». **Gola** — профиль со словом из «Gola, слова».

Шаблоны артикулов: через `;`, `*` — любые символы, `?` — один символ, регистр не важен; шаблон подходит ко всему артикулу
или к первому слову («71B3550 MB V250 NI» подходит под `71B3550` и `7?B*`).

| Шаблон | Что найдёт |
|---|---|
| `7?B*` | все Blum BLUMOTION: 71B3550, 79B9550.83, 71B453T |
| `*.TL` | всё на .TL (Blum без пружины под TIP-ON): 70T3550.TL |
| `70T*;78T*` | Blum без пружины: 70T3550.TL, 78T9550.83 |
| `956*` / `955*` | механизмы TIP-ON Blum (956A1002) / ответные планки (955.1008) |
| `9089632` | ровно один артикул |

«Без пружины» проверяется раньше «С пружиной» — 70T3550.TL не попадёт в пружинные, хотя подходит под `7?T*`. Если петля
распознаётся не так — впишите её точный артикул в нужное поле. Слова (`…, слова`) — через `;`, ищутся как часть названия,
регистр не важен. Изменения — после «Проверить (F5)».
